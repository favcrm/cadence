Consolidated plan · v7 · 2026-09-23 · Markdown source: design-plans/…/PLAN.md

An autonomous dev team that learns — on your machine.

One master assistant talks with you. It runs projects — a PM session per project, plus developer, QA and DevOps sessions of agents defined once as Markdown folders (agents/<slug>/ SOUL.md, AGENT.md, MEMORY.md). Every finished job, question or blocker produces a report; a verifier (deterministic checks plus a curator from a different vendor) turns reports into verified memory in a git company vault; every agent starts its next task with a small, cited context pack instead of re-reading. You approve what matters.

00Pragmatic core — build little, generically

Add only what is necessary, and make it generic enough to extend. Everything reduces to five building blocks; the rest is configuration or later.

01One master, many projects

Responsibility down

The master proposes a plan and its staffing (agents × sessions); you approve. The PM session owns the plan and dispatches inside it. One writer per code area; research and review run in parallel.

Reports up

Every job, question or blocker files a typed report: the six-field reflection, evidence, constraints copied verbatim, and feedback on the context it was given.

Questions climb, then stop

Worker → PM → master → you. The vault is checked first; a question stops at the first level that can answer it, and every answer becomes a decision nobody asks twice.

04Operating rules (enforced by the daemon, not the prompt)

Contract first

The PM writes testable acceptance before any code; QA verifies against the contract, never against the author's summary. MAST attributes ~44% of multi-agent failures to specification.

Independent review

Reviewers start in a fresh context. Different vendor by default, with pairings chosen by measured precision — cross-vendor review helped in one direction and hurt in the other in a 2026 study.

One writer per code area

Write leases per path set; parallel work is reads — research, review, triage. Peer swarms and single serial gates both failed at scale (Cursor, Anthropic C compiler).

Separation of duties

No agent reviews, merges or accepts its own work or lessons. A message from another agent never counts as your consent.

Evidence over self-report

"Done" is a claim until a verdict pins it to a commit; "tests passed" is re-run before a lesson is accepted.

Lean context

No repo overviews in packs; ~100 lines of non-standard rules; byte-stable prefixes for caching; fresh sessions over stale revivals.

Research · checked 2026-09-23

What actually works for teams of coding agents

A shallow hierarchy with one writer per code area, a PM that writes testable acceptance first, reviewers that start fresh, typed handoffs, and small verified context loaded on demand. Memory helps only when it is verified, cited, scoped and measured — most memory systems in a September 2026 benchmark did not beat memory-off.

Vendor numbers are self-reported. Many 2026 arXiv items are preprints — directional, not settled. Key memory claims were re-checked against primary sources; corrections are applied below.

02Roles, model routing and review

Roles are files

Claude subagent frontmatter sets tools, model, effort, permissions, worktree isolation, memory and turn limits; Codex agents use TOML. One versioned spec per role, compiled per vendor.

Mix models by role

Mixed-model teams gained up to +44% accuracy at equal cost, or matched accuracy at up to 12× lower cost (arXiv 2606.20629); an Opus advisor lifted Sonnet +2.7 pp at 11.9% lower cost.

Cross-vendor review is asymmetric

Claude reviewing Codex raised pass rate 71.6% → 89.7%; Codex reviewing Claude lowered it 91.4% → 82.8% (arXiv 2607.21656, reviewer could not run code). Separate-session review beat same-session review.

Reviewer reliability

Tool-using judges "dramatically outperform" plain judges; LLM review F1 fell from 0.657 on diffs under 10 lines to 0.043 over 150 lines (arXiv 2606.15689). Keep diffs small; tier review by risk.

03Communication and escalation

Typed handoffs

Cursor worker reports carry notes, concerns, deviations, findings; Factory keeps contract, feature list and knowledge base as shared state; OpenAI checks plans and decision logs into the repo.

Constraints get lost

Compressed handoffs keep facts but drop constraints (survival 0.80 → 0.57 at 25 words); stating constraints explicitly cut leakage below 15% (arXiv 2608.29028).

Ask, don't guess

Agents miss underspecification; asking clarifying questions improved results by up to 74% (Ambig-SWE, ICLR 2026). Claude Projects threads "guessed or stalled instead of asking".

Consent is human

A2A v1.0 (Mar 2026) models an input-required task state. Claude Code treats an approval relayed by another agent as untrusted.

06Verification and safety

Poisoning is real

AgentPoison: >80% attack success with <0.1% of memory poisoned. MINJA injects through ordinary queries. MemoryGraft plants fake "successful experiences" — exactly a lesson bank's risk. OWASP lists memory poisoning as ASI06.

Defenses that work

Provenance on every item, citation checks at use, read-only shared stores with a proposal queue, consensus checks across related memories (A-MemGuard, >95% fewer successful attacks), and quarantine for anything derived from external content.

Different judge, different vendor

In rubric-based evaluation, judges "can be more than 50% more likely" to wrongly pass their own model's output (arXiv 2604.06996). Proposer ≠ acceptor, and different vendors, for both QA and curation.

Never trust "tests passed"

Re-run cited tests during verification. Self-improving agents have faked test logs (DGM).

07Skills and knowledge vaults

Skills help when curated

Agent Skills (open standard, Dec 2025; supported by Codex, Copilot, Cursor, Gemini CLI, OpenHands, Letta) load in stages. Curated skills lifted average pass rate 33.9% → 50.5%; self-generated skills landed below the no-skills baseline in all three tested configurations (SkillsBench v4, Jun 2026). Keep skills small, curated by a strong model, and promote only with a test showing benefit.

Guidance files can cost more than they give

AGENTS.md-style context files generally didn't raise success and cost over 20% more tokens (arXiv 2602.11988). Packs must be lean and task-specific, not a repo overview.

LLM-maintained wikis

Karpathy's "llm-wiki": raw sources untouched, an LLM-owned markdown wiki with schema, index, append-only log, and a lint pass for contradictions and stale pages. Google Code Wiki regenerates after every change and links to code.

Scopes

Company (read-only) → team → project/repo → role (path rules, skills) → user — the same layering Claude Code, Devin and Managed Agents use.

08Context engineering — so agents don't re-read

Context rot

All 18 models tested degraded as input grew, even on simple tasks (Chroma, Jul 2025) — the reason reviewers and workers get fresh contexts.

Progressive disclosure

Skills load name → body → files; MCP tools as code on disk cut 150k → 2k tokens; clearing stale tool results cut 84% of tokens and, with a memory tool, gave +39% (Anthropic, 2025).

Maps and indexes

Aider's ranked repo map (~1k tokens); RepoGraph +32.8% relative on SWE-bench; Cursor reuses indexes by content hash (time-to-first-query 7.87 s → 0.53 s). No public system documents SHA-keyed summaries as such — content hashing is the closest.

Caching economics

Cache reads bill at ~0.1× input; static content first and byte-stable prefixes; Manus calls cache hit rate the key metric. Reviving a stale session re-reads its history.

09Evaluation — is it getting better?

Passing ≠ mergeable

About half of SWE-bench-passing PRs would not be merged; maintainer acceptance ran ~24 points below the grader (METR, Mar 2026).

Memory must earn its place

VibeMemBench (Sep 2026): 11 of 12 memory-system/solver pairings failed to beat memory-off; injecting verified past experience gave +1.1 to +4.5 points and fewer steps.

Benchmarks that fit roles

SWE-bench Pro (contamination-resistant), SWE-Lancer manager tasks for PMs, Terminal-Bench 2.0 for DevOps, TheAgentCompany for whole-team work (best agent 30%).

Our own replay suite

Closed Cadence tickets become a replay set; measure merges without rework, cost and wall-clock per merged PR, escalations per task, review precision on seeded bugs — by vendor and task type.

Thread ≠ provider session

The master's conversation is a Cadence thread. A provider session is disposable: when it is lost, compacted or the provider changes, a new session starts with the continuity pack (summary + last N turns + plan state + preferences) instead of blank.

Summaries without extra spend

The master writes a checkpoint summary at plan approval and every ~40 turns as part of its own turn; Cadence stores it. No hidden model calls.

Backup that is a backup

cadence backup uses SQLite online backup + manifest (schema, sha256, versions); nightly by default, keep 7. Replaces receipt-only rollout backups and gates self-update.

Export / restore

cadence export --bundle → one file: store snapshot, tracker remote, repo map, briefings. Credentials excluded, secret-scanned. cadence restore or wizard "Restore a backup".

Retention

Roll up delivery-noise events (30k of 50k live rows are submitting); archive threads, never silently delete; agent rm keeps thread history unless asked.

Platform sync (optional)

Encrypted bundle to the platform's files API (AgenticOS v2 files merged, AOS-41) and a status projection of plans/threads — the platform never becomes the authority (AOS-34 rule).

Context pack — built at task start

  1. Inputs: role, task (issue, planned paths, labels), budget. Static parts first so prompt prefixes cache.
  2. Select: role handbook excerpt → contract (acceptance, constraints, non-goals verbatim) → project context → lessons by path, then similarity, then role → FAQ → skills by name.
  3. Re-check each lesson's citations against HEAD; withhold stale or contradicted items with the reason (CAD-203).
  4. Rank by confidence × helpful rate × recency; cap to the role budget; render each item with "verified at SHA" and its citation.
  5. Log included ids for the report's context feedback; the same builder serves issue dispatch, --job dispatch and continuity (CAD-194, CAD-324).

09Connected platforms — AgenticOS v2 as reference

Cadence integrates with a platform contract, not a vendor. AgenticOS v2 is the first implementation; a user's own Cloudflare account is the second.

1 · Connect

Credential exchange started by the operator: device-style code, platform sign-in, scope consent, revocable credential returned to Cadence. No cookies copied.

2 · Tools

MCP tools (local proxy first, remote Streamable HTTP later). Every tool declares an effect: read, draft, send (message, publish, deploy, spend).

3 · Effect gate

read/draft run within scope. send returns a pending effect; the operator presses it in Cadence (and the platform may ask again). Agents never execute sends.

4 · Usage & files

Optional: model access (gateway), usage/credits read-out, file storage for encrypted backups, status projection.
