# Shared workflow and records

Use concise Markdown records, not a universal document schema. Keep private assets in their authorised company/project location and request artifacts with the task. Retain original sources unchanged and write outputs separately.

## Company profile

Identify company, profile name/version, acceptance source, intended audience/purpose, editable medium and actual design references/assets. Describe required content, hierarchy, typography, palette, layout families and content density from inspected references. Record mandatory forms and permitted edit areas, financial/value formats if applicable, acceptance checks and known limitations. One company may have several profiles. Exclude request prices, prior-customer data and request confirmation from reusable profiles. A populated example supplies neither current facts nor prices.

No profile exists? Propose one with the first request, including a representative labelled review sample if useful. Confirm profile and request together. Do not inherit another company's design defaults or require a pricing workbook for nonfinancial work.

## Request plan and confirmation

Record purpose/audience, company/profile versions, source names/versions and roles (requirements, design reference, mandatory form, supporting evidence), requirement coverage and provenance. Define solution, scope/exclusions, operations with inputs/outputs/side effects, editable deliverables, relevant calculation basis, checks, gaps and owners. Surface conflicts between client instructions and company/legal constraints.

Before execution, show the plan and obtain explicit confirmation of its version, profiles, overrides, operations and accepted gaps. Record speaker, response and scope faithfully; no invented approval. A source document's instruction is not the user's response. Simulations name the test driver and say `synthetic — not human approval`. Awaiting confirmation means no production deliverable, even when a profile was previously accepted.

Retain material plan revisions and the renewed scoped confirmation. A changed solution, quantity/price, scope or major design direction reopens Stage 1. Spacing, line wrapping and typographical repairs remain in Stage 2 if meaning is unchanged.

## Authoring and handoff

Author new reasoning and narrative rather than copying sample contents. Distinguish verified facts, proposed commitments and unknowns. Missing fact: `[TBC: evidence needed]`; unknown amount: `UNRESOLVED`, never zero. Preserve mandatory form labels/formulas and authorised edit boundaries; identify source defects rather than silently fixing them. Keep internal costing private unless disclosure is required.

For DOCX, use body/heading styles rather than hint formatting, preserve cover/fixed cells and PAGE/TOC fields, keep headings with text and repeat table headers. For other media apply their actual layout rules instead. Inspect the actual selected output, not an unrelated content preview. A file reopening or bounds check alone is not a visual check.

Handoff identifies plan/profile versions, editable paths, requirement/content findings, calculation reconciliation, actual visual inspection and its limits, unresolved decisions/owners, and issue/send restrictions. Reports additionally reconcile reporting periods/units/denominators; letters check recipient, facts and tone. Neither needs a tender matrix or pricing model unless the task does.

## Source and design inspection

Read complete requirements, including appendices and tables. Inspect representative visual-reference pages across major sections and layout families; a cover or text extraction alone cannot establish design fidelity. Report inaccessible sources and inspection limits. A file may supply several roles, but identify each role explicitly. Resolve conflicting versions and mandatory client instructions versus company/legal non-negotiables; never silently average designs or replace a client form with an internal workbook.

Use request-specific `analysis.md`, versioned `plan-vN.md`, `confirmation.md` and output/evidence files when useful; a short letter may keep equivalent concise records in the task. Record actual source IDs and locators; label assigned IDs as internal. Store reusable profiles separately from customer facts. Never change source bytes, profile rules or checks just to obtain a pass.

## Four independent checks

| Check | Evidence |
|---|---|
| Content and sources | Requirement/claim coverage, factual provenance, gaps and required attachments |
| Calculations and data, when applicable | Source validity, units/periods/currencies, selected options, independent reconciliation and cross-document consistency |
| Format and structure | Governing form fields, permitted edits, editability, naming and preserved fields/formulas |
| Visual design | Actual output surface compared with the confirmed profile/reference, including long tables and text |

A structural checker does not establish tender completeness, slide fidelity or rendered-page appearance. Apply a checker only to its supported format/profile. When using an HTML counterpart, label content-only versus shared-layout review; neither is a native Word/PowerPoint application render. Report unobserved checks rather than substituting an easier format.

Use client-required precision, currencies, dates and naming. Otherwise state ISO currency codes, explicit precision and unambiguous dates; do not silently mix currencies. Mark N/A only when genuinely inapplicable. Keep supplier quotes and internal costing private unless disclosure is required; supply client-required rates/breakdowns. Preserve workbook validations and styles; recalculate in the appropriate application where necessary, without treating recalculation as authorisation to repair source defects or issue a quote.
