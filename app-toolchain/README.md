# Cadence app tooling

This archive is a versioned starter toolchain for app-owned React/Vite projects. It contains pinned React 19, Vite 8, and the React Vite plugin, a frozen pnpm lockfile, and the canonical Cadence frame kit. It is tooling only: it is not a Cadence SDK, app runtime, authorization grant, or requirement that apps adopt a particular architecture.

## Start a private app project

This archive is generated and tested with Node.js 22 and pnpm 12.2.1; `toolchain.json` records the exact package-manager pin for this release. Download `cadence-app-toolchain-<tag>.tar.gz` and its `.sha256` sidecar from the same Cadence GitHub Release. Verify the sidecar before extracting; verify the GitHub build-provenance attestation against the release tag and Cadence workflow before relying on the artifact. Keep the archive's `package.json`, `pnpm-lock.yaml`, `toolchain.json`, and `LICENSE` together in your app-owned project.

Install without changing the reviewed dependency graph:

```sh
pnpm install --frozen-lockfile
```

Create an app-owned `index.html` and `src/main.jsx`, then run:

```sh
pnpm build
pnpm dev
```

The ordinary Vite scripts and files remain app-owned; this package adds no lifecycle/install scripts or Cadence-specific harness.

## Canonical host frame

The `frame-kit/` files are generated by the matching Cadence CLI release, not an independently copied renderer. To get a frame mounted with your app's validated local bundle, run the same versioned CLI and provide an unused output path, the app bundle, and the real parent origin:

```sh
cadence app frame-kit --out /tmp/my-app-frame \
  --bundle ./path/to/app-bundle --parent-origin http://127.0.0.1:5173
```

The default exported frame is an empty offline reference. For an app smoke test, serve the exported frame and mount your application using the actual `--parent-origin` and `--bundle` values. Do not patch generated renderer bytes, replace the host bridge, or treat the empty reference as a running app integration.
